VKYC · Account Verification

Account blocked / invalid — with next-step education

Shown when the bank account can’t be verified — either the bank has blocked it, or the details are invalid. A retry alone won’t fix a blocked account, so each screen briefly educates the user on why it happened and what they can do, then offers a clear retry and exit. Same design language as the payment and error screens.

Design intent

  • Educate, don’t just block — a blocked/invalid account is a dead end without guidance, so every screen answers “why?” in one line and “what now?” in two short, plain-language points. No jargon, no bank error codes.
  • CTA emphasis follows the cause — for an invalid account a corrected retry usually works, so Retry is primary (B). For a blocked account retry won’t help until the bank acts, so retry becomes “try a different account” and Exit / Support carry more weight (A, D).
  • Exit is always available — never trap a user who genuinely can’t proceed; Exit is present on all four, styled quietly so it doesn’t compete with the recovery path.

Recommendation

  • If your backend can distinguish the two cases, use B for invalid details and A for blocked accounts — the tailored guidance converts better.
  • If it returns a single “can’t verify” signal, ship C — it covers both causes honestly without guessing.
  • Add D’s support path only for markets/flows where users routinely need human help to resolve a block.
