Generic server error — neutral, low cognitive-load

One calm, generic screen for any unexpected server error. No status codes, no reference numbers, no “it’s our fault” — nothing for the user to read, decode, or act on except a single retry. Same design language as the payment screens. Four wordings of the same neutral message.

What changed

  • Nothing random on screen — the reference/incident code is gone from the UI. If you need it for debugging, capture it silently in your logs; the user never sees it.
  • No blame framing — dropped “it’s not you, it’s us”. Every headline is a plain, neutral statement of fact.
  • One generic message for every error — 500 / 502 / 503 / timeout all render the same screen. No codes, no cause, no decision.
  • Recommendation: ship A · Something went wrong as the default. Use D only if a support entry point is required on this screen.
